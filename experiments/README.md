# 动态 OT 实验：新服务器起点

当前远端仓库原先仅含研究网站。这里从零搭建实验；没有导入旧服务器成果。
旧服务器的 77 个留出时间点和 46.2% 改善未在本工作区恢复或复现。本机已完成基线、固定预算动态 CTD、共享外观优化、离线 split 和约简模型训练循环中的单次 split 门控；完整 4DGS 自适应致密化尚未实现。

## 存储与准备

根目录 `/data3/store1/<当前用户名>/`，所有数据、环境、缓存、模型和实验输出必须位于此处。
`source scripts/common.sh` 会加载根目录的 `migration-env.sh`，并把工具 HOME 隔离到数据盘。
不得在 `/home` 安装，不得运行 `conda init`，不得覆盖已有实验。

1. `bash scripts/bootstrap_env.sh`：校验安装包 SHA256，在数据盘安装 Miniforge 与 Python 3.10 / PyTorch 1.13.1 cu117 环境，从 NVIDIA 官方再分发包安装最小 CUDA 编译工具链到 `envs/cuda-11.7.1/`（SHA256 已固定），使用 GCC 11 编译两个 4DGS 扩展。
2. `source scripts/common.sh; source "$RESEARCH_ROOT/miniforge3/etc/profile.d/conda.sh"; conda activate "$GS_ENV"`。
3. `python scripts/preflight.py` 检查存储、仓库、缓存和已有数据；`--require-ready` 同时要求数据与依赖完整。
4. `python scripts/verify_env.py` 做小规模 CUDA KNN 与光栅化前后向验证，不训练。
5. `python scripts/prepare_bouncingballs.py` 从 4DGS README 给定的官方 D-NeRF 链接下载数据，只解压 bouncingballs；在数据目录生成每个文件的 SHA256 清单。已有目录只检查，不覆盖。
6. `python scripts/baseline.py --gpu 0` 只显示完整训练命令。确认 GPU 调度与检查通过后，`--run` 才会启动训练；每次创建新输出目录，并保存日志、运行 manifest 和 pip freeze。

基线使用官方 bouncingballs 配置（coarse 3000 / fine 20000，源代码种子 6666）。源数据和模型目录始终以绝对路径传入。默认 GPU 0 是待调度参数，不代表预留了该卡。

## 实验顺序与判据

- E00：下载官方 D-NeRF bouncingballs，核对 train/val/test 元数据及每张图像；保存来源和哈希清单。
- E01：原始 4DGS 基线；独立输出目录、固定种子、记录 Git SHA、完整命令、环境清单和 cfg_args。
- E02：固定高斯预算的逐帧 GHAP 与共享轨迹约简对比，先比较分布误差、时序残差、PSNR/SSIM/LPIPS 与耗时。
- E03：位置/协方差/速度项消融；训练时间与留出时间分开，不先假定速度项有效。
- E04：跨训练时刻共享 SH/opacity 外观微调；由前面结果决定是否推进。
- E05：离线 CTD split 候选及预算／顺序稳定性验证。
- E06：约简模型训练循环中的单次 split 接受事件及同数量对照；完整 4DGS 训练期自适应 split/merge 仍为研究目标。

不把训练后固定预算约简称为自适应致密化。暂不进行真实物理守恒的结论推断。

## E02：固定预算 CTD 对照（2026-11-03）

完成 5000／10000／20000 三个预算、每个预算全部 150 个时间点的单种子对照。逐帧方法是每个评估时间重新拟合的 oracle；共享方法只用 76 个时间拟合固定分组，再应用于其余 74 个时间。底模见过全部这些时间。使用真实激活后的均值和完整协方差，时间共享 SH/opacity；状态重渲染与原生渲染的最大像素误差为 6.56e-7。
这是 GHAP CTD 核心适配，并非官方完整流程复现。代价为位置平方差加协方差 Frobenius 平方差，不是 KL 或高斯 W2。采用全局分块距离、float64、精确预算空簇修复和直接协方差渲染；原始仓库未修改。共有 50 轮上限，各预算共享拟合及 150/150 个逐帧拟合均收敛。20 轮试跑保留为独立记录。

| 高斯预算 | 逐帧 PSNR | 共享 PSNR | 共享时序残差相对降幅 |
| --- | --- | --- | --- |
| 5000 | 29.012 | 28.763 | 42.5% |
| 10000 | 33.828 | 33.615 | 30.7% |
| 20000 | 39.349 | 39.233 | 21.9% |

PSNR 为原始 20 个测试视图、保存等价 8-bit RGB 的均值；LPIPS 按标准 normalize=True 口径记录在完整报告。时序残差为固定相机 256 分辨率下，约简与完整底模的相邻 RGB 帧差之差的平均绝对值，不是轨迹速度误差，也不是旧实验的 46.2% 指标复现。共享方法在三个预算上残差更低，但 PSNR 和 LPIPS 略差。单场景、单种子，仅支持当前设置下的初步取舍结论。
输出状态仍依赖完整底模轨迹，不能宣称已经获得独立压缩的动态模型或推理加速；未做外观微调、速度项或自适应 split。下一步是固定几何，对共享 SH/opacity 做受控微调。汇总路径见 `e02-status-20261103.json`，详细协议见 `reduction-ctd-v2.json` 及迭代上限补充 `reduction-ctd-v2-refinement.json`。

## E05：离线 CTD split 候选初验（2026-11-04）

在 E04 联合微调后的共享 K10000 表示上，固定新增 256 个高斯。只用 76 个拟合时刻，在每个原父分组内做加权轨迹二分，四种评分共享同一套子分组：五个等时长窗口平均收益的最小值、全拟合时间平均收益、首帧收益、随机抽样。首帧组只消融评分，不是完整的独立逐帧算法。分组身份固定后在全部 150 个时刻应用，仍依赖完整底模轨迹。

五组均从 E04 外观出发，再用相同视图顺序优化 1520 步 SH／opacity；包含不 split 的继续微调对照。分裂子节点继承父 SH，按混合权重比例分配光学厚度；只在重合足迹假设下保持透射率，不保证不同几何下初始图像完全不变。

窗口组较同新增预算随机组 PSNR 高 0.2643 dB；较不 split 继续微调高 0.3976 dB、时序残差低 9.12%，但后者高斯数量不同。全局组 CTD 降幅最大而画质略逊于窗口组，不能只按 CTD 判优。当前只有单场景单种子，不据此确认统计显著性。

成功运行：数据盘 `outputs/ot/e05-split-20261104T103723Z/`；验证结果位于 `validation/`，报告／CSV／图在 `validation/analysis/`。状态见 `e05-status-20261104.json`，预设协议见 `split-proposal-v1.json`。

这实现的是训练后、固定新增预算的离线 split 原型，尚非训练期自适应致密化，也没有 merge、可变 N(t) 或独立压缩 deformation。下一步先扩大种子和预算验证评分可靠性，并结合实际渲染收益，再推进训练期 split/merge。

新增 256 的三组汇总（均值±样本标准差）：窗口 PSNR 38.0871±0.0008 dB，全局 38.0444±0.0003 dB，随机 37.8061±0.0155 dB。窗口相对各自随机对照的配对 PSNR 增益为 0.2643／0.2837／0.2951 dB，时序残差分别低 7.181%／7.181%／7.330%。这些是小规模稳定性描述，不作统计显著性结论。窗口在三个预算的测试 PSNR 均最高；128 预算的时序残差略逊于全局评分，不能宣称所有指标均最优。

顺序生成修订：原 E05 使用 seed+epoch，相邻种子重用许多 epoch 排列。v2 运行全部保留；在尚未按这些结果选择方法前，预设 v3 修订，保留三个 seed42 预算结果，重跑 256 的种子 43、44，采用 SeedSequence(seed).spawn(epochs) 生成独立的 epoch 流。实际顺序检查确认 42／43／44 组间共享的 epoch 排列数均为 0。原 legacy43/44 不混入本汇总。即便如此，底模和几何分组未变，这仍不是完整流程独立多种子验证。

验证：相同预算下三个确定性评分的几何文件跨顺序种子 SHA256 完全相同；128／256／512 的评分前缀嵌套；三个 seed42 条件训练顺序相同。不 split 对照重复运行 PSNR 极差为 0.000659 dB，故保留各次真实数值、用各自对照计算配对增益，不假设 CUDA 反向逐位可复现。各条件另核对几何预算、输入／源码哈希、实际源样本 SSE 收益、有限 checkpoint、步数及 20 视图均值。

修订后汇总根目录：数据盘 `outputs/ot/e05-robustness-amended-20261104T110951Z/`，内含复用记录、新增两组输出、`analysis/report.json`／`conditions.csv`／`robustness-summary.png`。预算 128／512 及旧重叠排列结果保留在 `outputs/ot/e05-robustness-20261104T110338Z/`；旧 256／42 试验未改。协议见 `split-robustness-v2.json` 与 `split-robustness-v3.json`，状态见 `e05-robustness-status-20261104.json`。

接下来的研究问题是将候选评分接入训练循环：在预定训练阶段提出少量 split，用拟合窗口的实际渲染收益和复杂度代价决定接受，再在未用于决策的时刻／视角评估。当前仍是训练后、固定新增预算的离线验证，没有训练期自适应 split/merge。

## E06：约简模型训练循环中的一次 split 事件（2026-11-04）

在 E04 外观初始化上先训练 760 步，保存共同模型与 Adam 暖启动，再分出五个分支；在第 760 步插入一次容量事件，之后各训练相同的 760 步。CTD 候选来自 E05 的固定 76 时刻子轨迹与窗口／随机列表，每批 16 个父分组，最多新增 256 个高斯。几何和完整 4DGS 教师冻结；这不是完整 4DGS canonical／deformation 训练中的致密化，也没有 N 随物理时间变化。

接受判据预先固定：每批将当前主模型和 Adam 克隆为不分裂／分裂两个试跑分支，在 56 个拟合视图中的相同 20 个视图上各更新 20 步，再在另外 20 个拟合视图（每个时间窗 4 个）比较渲染损失。平均收益必须超过每新增高斯 1e-7 的复杂度代价，且任何拟合时间窗口的平均损失不能恶化超过 1%。这些决定视图仍属于原拟合集。74 个留出时间与测试指标不参与决定。

两条试跑分支的权重都丢弃；接受时重新把 split 应用到试跑前的主状态，拒绝则主模型、优化器完全不动。原行保留参数与 Adam 一／二阶矩；被分裂父行和新增行的矩置零，SH 继承父当前有效值，opacity 按光学厚度拆分。Adam 的共享标量步数保留，不宣称子节点单独从 step0 开始。

各主模型逻辑上训练 1520 步，但共同的 760 步暖启动只计算一次。四个候选分支各额外计算 640 步试跑更新（16批×2反事实×20步），总计 2560 步；不分裂对照没有这些开销。因此主更新步数相同不等于总计算量相同。强制接受分支也计算诊断分数但不据此筛选；不同分支的门控分数随此前接受的几何状态变化。
